# v0.1.12

修复 `0.1.11` 已知问题：安装器新增 `assert_real_dir_ancestors` 守卫，在写入
`.agents/skills/handoff`、`.agents/tasks/archive`、`.claude/skills`、`tools` 之前逐级检查路径
祖先是否为符号链接，是则拒绝安装并报错，不再跟随链接在目标仓库外写入持久 handoff 文件。
覆盖两种场景：`.agents` 本身是目录符号链接，以及符号链接嵌套在 `.agents` 内部（如
`.agents/skills`）。`tools/verify/test-install.sh` 新增两个回归用例验证拒绝行为且不改动
仓库外目录。

# v0.1.11

运行时交棒保留最近一次 ack、仅清空 owner，接棒先判断占用和已有授权；最终交棒与归档使用一次
带完整 trailer 的提交，并确保 clone 后首次归档目录存在。建棒复用当前会话已明确给出的信息。

补齐活动任务棒与归档的压缩预算：收拢 Done 和陈旧 Decisions，保留有效状态与 Git 原文定位。
只有用户要求读取压缩前内容时才回读；历史引用、摘要缺口或排查需求不自动授权加载旧正文。

安装器按数字比较版本、禁止降级；采用旧载荷后记录版本未知并允许显式更新，恢复事务必须匹配
当前安装包。账本按解析后的 Task-Id 完整值过滤，避免同前缀任务及正文引用串账。

已知问题：本版本未处理 `.agents` 为目录符号链接时安装器会跟随链接、在所选仓库外写入持久 handoff
文件的边界；该行为已在隔离临时仓库复现，待后续修复。

# v0.1.10

不改行为，只让声明与内容相符。外层 skill 的 description 不再只自称安装器，而是明说本包交付的是
仓库级 handoff 协议、安装后会有一个运行时 skill 管辖该仓库未来会话的开工与交接；同时保留「不用于
日常任务接力」的窄触发边界。SKILL.md 开头新增「这个包的两层结构」一节，说明 `assets/` 下的运行时
协议是待安装的载荷、在本包内不被加载或执行。载荷文件顶部也加了同样的范围说明。

回应 SkillSpector 对「元数据声明为安装器、正文却是工作流」的判定：该判定把载荷内容当成了安装器
自身的指令，两层结构此前只体现在各自的 frontmatter 里，未在正文显式声明。

# v0.1.1 首次公开发布

Agent Handoff 将可审计的多 agent 任务接力协议安装到 git 仓库中。首次发布包含：

- 显式触发的 `handoff-installer` Skill
- `status`、`install`、`update`、`adopt-existing` 四种模式
- 安装锁、本地修改保护和中断恢复
- 仓库运行时 handoff Skill、任务棒模板和只读账本工具
- 四客户端触发与干净安装结果接棒验证

该版本不包含 MCP server、远程服务、认证、遥测或托管数据。
