## Agent 接力协议

开工前读 `.agents/tasks/current.md`。没有活动任务时按当前请求正常开工；draft 先确认尚缺信息，
当前会话已明确提供的目标与禁区不重复询问。done 与 Next 或工作区不一致时，先说明并明确工作归属。

接棒先检查 owner：其他 agent 持棒且尚无接手授权时等待用户决定；已有明确授权直接继续。
在写入 ack/owner 前，用自己的话复述 Intent 与 Next 第一条，核对理解及前置条件；有缺口先说明，
不能执行的前置记入 Open questions。确认可接手后，把本轮复述覆盖写入 ack，owner 写成自身 CLI 标识。
ack 非空不代表当前有人持棒，不能沿用旧复述代替本轮确认。

日常接棒以当前任务棒为准，查询归档先读当前摘要。**只有用户要求读取压缩前内容时，才读取对应历史
原文。** SHA、路径或摘要缺口均不构成读取授权；排查、审计、核实也不例外，不自动展开或递归跟读。
用户要求读取后只读指定范围。账本摘要查询和来源对象存在性检查不自动加载旧正文。

每次交棒及归档前检查压缩：Done 超过 10 项，或全文超过 200 行/6,000 字符即整理，归档目标为
3,000 字符以内。改写前仅以对象存在性及 git diff --quiet HEAD 的状态码确认本次输入已提交，
不显示任务棒的正文 diff。只移出确认过的历史内容并保留完整 SHA 与原路径；必要状态及未提交的新信息
不能为了预算丢掉。Decisions 保留有效判断与理由，陈旧过程可以摘要化；历史可追溯，不无限堆正文。

交棒更新 Done/Next/Decisions 和其余小节，hop 加一、updated 更新时间，**只清空 owner，保留 ack**。
任务完成时先更新状态并检查摘要，创建归档目录，暂存修改后再 git mv；最终交棒和归档只提交一次。
任务棒只在任务分支上；无本任务分支时先创建，归档后才能合并回主干。

每次交棒提交带三行 trailer，放在同一个 -m 参数中，彼此换行：

    git commit -m "<英文单行总结>" -m "Task-Id: <任务棒里的 task>
    Hop: <更新后的 hop>
    Agent: <自身 CLI 标识>"

Agent 填自身 CLI 标准标识（如 claude-code / codex / zcode / kimicode），不能从 owner 或历史抄身份。
准确归属若与更高优先级规则冲突，提交前说明冲突，不自行声明规则例外。

详细状态处理、压缩保留项和完整归档命令见 `.agents/skills/handoff/SKILL.md`。
