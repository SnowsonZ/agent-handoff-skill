# 任务接力规程

> 本文件是全局 `handoff-installer` Skill 的运行时规程。任务棒和归档留在目标 git 仓库，规程、
> 模板和账本脚本从已安装的全局 Skill 读取，不复制到仓库。

每次开工先读取本规程；本轮已读取且文件未变化时无需重复读取。随后检查当前任务棒和工作区状态，
按下述状态分支处理；没有活动任务时按当前请求正常工作。

当前任务状态以 `.agents/tasks/current.md`（任务棒）为准。历史用于追溯，不是另一份当前状态。普通
请求在没有任务棒时正常处理，不自动建棒；没有旧部署时不创建 `.agents/` 或迁移记录。

## 读取边界

- 日常接棒读取当前任务棒；用户要求查询归档时，先读相应归档的当前摘要，不扫描全部旧任务。
- **只有用户明确要求读取压缩前内容时，才读取对应历史原文。** SHA、原文路径及摘要中的引用
  只是追溯入口，不是必读清单；不得自动展开、递归跟读或把压缩前全文重新灌入上下文。
- 摘要有缺口时说明具体缺口，不自动补读。排查、审计、核实需求本身，以及你认为“需要更多背景”，
  都不等于读取压缩前内容的授权。得到读取要求后，只读取用户指定范围；已有明确要求不重复询问。
- 历史判断不能直接覆盖当前有效结论。`<skill-dir>/scripts/ledger.sh` 的摘要查询、提交号及
  对象存在性检查
  不读取历史原文，可以用于查账和验证来源。

明确只读查账、审阅或解释规程时，不进入下面的接棒流程，不需要接手 owner；只运行必要的
`python3 "<skill-dir>/scripts/migrate.py" status` 或全局只读账本，不迁移、不写任务棒。全局入口配置请求
也不接棒，按 SKILL.md 的配置模式处理。

## 开工检查旧部署

旧部署清理独立于任务创建。全局入口发现旧锁、清理事务或旧部署痕迹时，即使没有
`current.md`，也运行 `python3 "<skill-dir>/scripts/migrate.py" status`。
明确只读请求及全局配置请求沿用上面的边界；有任务棒时先按「接棒」检查状态和接手授权。
没有任务棒且当前请求允许工作区写入时，`legacy` 或新清理事务的 `interrupted` 自动执行
`python3 "<skill-dir>/scripts/migrate.py" migrate`，确认 `clean` 后继续原请求，不建棒、不接手 owner。
`clean` 直接继续；`blocked` 或命令失败则报告具体问题，停止清理，不猜测旧规程。
无锁旧部署只报告归属问题，不删除。旧安装事务必须由原版本恢复。
迁移改动留在工作区供正常审阅提交，不自动提交，也不读取任务历史。

## 接棒

先读任务棒和工作区状态，先按下表处理任务状态，再检查 `owner` 是否属于其他 agent 以及当前会话是否已有明确接手授权；若 owner
属于其他 agent 而未获授权，立即停止并等待用户决定，不能迁移或改写任务棒。确认可接手后，在第一段任务
回复中，用自己的话复述 Intent 与 Next 第一条；理解有出入先确认，不动手。明确只读查账或审阅时，只运行
`python3 <skill-dir>/scripts/migrate.py status`，不得迁移或改写任务棒。

**在改 `ack`、`owner` 之前**处理下列情况：

| 状态 | 动作 |
| --- | --- |
| 文件不存在 | 无活动任务，正常处理当前请求；需登记延续性工作时按「建棒」执行 |
| `draft` | 先确认仍缺失的目标或禁区；已有当前会话明确确认则直接启动，不重复问 |
| `done`，Next 为空且无新改动 | 已完成，无需接棒；可按用户请求归档 |
| `done`，但 Next 未清空或其他文件有新改动 | 说明遗留项和工作区现状；当前请求未说明归属时请用户明确，不自行归入旧任务 |
| `done`，Next 为空且只有任务棒有未提交改动 | 可能是收尾中断；核对当前请求后续走完成流程，不另起新任务 |
| `owner` 是其他 agent，且当前会话尚无接手授权 | 提示持棒者并等待用户决定；已有明确接手授权时直接继续 |
| 缺字段、小节，或任务棒与现场不符 | 说明缺口；能可靠接手的部分继续，缺口记入 Open questions；不自动回读压缩前内容或会话历史 |

Next 没有待办时写 `- (none)`，该行算空。多个异常同时存在时一起说明，不能因为其中一项满足就
忽略其他问题。`blocked` 先检查所记阻塞是否解除，未解除就说明阻塞，不假装已开始执行。

状态允许接棒后，在任何任务棒改写前运行 `python3 "<skill-dir>/scripts/migrate.py" status`。
`clean` 表示没有旧部署，不创建文件；`legacy` 或新清理事务的 `interrupted` 则运行
`python3 "<skill-dir>/scripts/migrate.py" migrate`，确认返回 `clean` 后继续。
`blocked` 或命令失败时停止写入任务棒。旧 `.agents/handoff.transaction` 会得到 `blocked`，须先用原版本
恢复；不得自动调用旧安装器。清理产生的已有工作区改动不混入业务提交。

用 `git cat-file -e HEAD:.agents/tasks/current.md` 和 `git diff --quiet HEAD -- .agents/tasks/current.md`
的状态码确认本次正文是否已提交；都成功时记住完整 HEAD SHA、原路径和本次输入，作为压缩基线。
只做无正文输出的检查，不显示任务棒正文 diff 或回读旧版本。已有改动或无法确认时保留不确定内容。

确认可以接手后：

1. 核对 Next 第一条前置条件；不成立就记录到 Open questions 并告知用户，不执行依赖它的步骤。
2. 任务棒只在任务分支上；没有本任务分支时先创建，归档后才能合并回主干。
3. 将本轮复述压成一到两句，**覆盖** frontmatter 的 `ack`，并把 `owner` 写成自己的 CLI 标识。
4. 开工。`ack` 记录最近一次接棒理解，非空不代表本轮已接棒；即使旧 ack 看起来仍正确也必须重写。

你的 CLI 标识由自身身份决定（如 `claude-code` / `codex` / `zcode` / `kimicode`），不能从
`owner`、`ack`、Decisions 或 git 历史推断或照抄。准确归属若与更高优先级规则冲突，提交前说明冲突，
不自行声明规则例外。`owner` 记录持棒人，不是身份指派或并发锁。

## 交棒

1. 本轮完成项移到 Done，使用 `- [x]` 并附产物路径和验收证据；Next 只留未完成项。
2. 重写 Next，第一条写清产物路径及验收条件；删掉参考链接后仍可执行。无待办写 `- (none)`。
   若目标或验收尚未达成，必须写出缺失的下一步，不能用空 Next 表示“暂时想不出”。
3. 记录本轮 Decisions（选择、理由、重要排除项及日期/agent），更新 Open questions 和 Do not。
   新判断替代旧判断时说明理由；陈旧过程按下节压缩，不无据抹除判断历史。
4. 按「压缩」检查长度。未完成任务的关键状态不能为了预算被删掉。
5. `hop` 加一，`updated` 更新为带时区的 ISO8601 时间；**只清空 `owner`，保留本轮 `ack`**。
6. 还有待办时提交本轮产物和任务棒；Intent、验收均达成、Next 已空且无遗留阻塞时，改 `status: done`
   并直接进入「完成与归档」。**最终交棒与归档只做一次提交，不先提交一遍再重复记录同一 hop。**

每次交棒 trailer 的 Hop 都照抄更新后的 frontmatter；Task-Id 照抄 task，Agent 填自己。
三个 trailer 放在同一个 `-m` 参数内，彼此换行；Git 只解析最后一个段落为 trailer：

```sh
git add <本轮产物路径> .agents/tasks/current.md
git commit -m "<英文单行总结>" -m "Task-Id: <task>
Hop: <hop>
Agent: <agent>"
```

只暂存本轮负责的文件。在目标仓库根目录用 `sh "<skill-dir>/scripts/ledger.sh" <task>` 查提交摘要，核对 hop 连续且无重复；
这不会自动加载历史任务正文。

## 压缩

### 何时整理

每次交棒和最终归档前检查整个任务棒（含 frontmatter）：

- Done 顶层完成项超过 **10 项**，或全文超过 **200 行**，或超过 **6,000 个 Unicode 字符**，触发整理。
- 最终归档整理为摘要，目标 **3,000 字符以内**；仍保留七个小节。
- 长度是整理触发器，不是删信息或阻止交接的硬门槛。必要信息或本轮未提交信息仍超预算时保留它们，
  在 Done 的说明中简要记录超出的原因。不要为达标删掉待办、约束或未解决问题。

### 怎样整理

1. 使用本次已读取的正文和改写前确认过的已提交基线，只移出其中已提交的历史内容。接棒之后新增的
   信息保留，不因 owner/ack 的本轮改写丢掉先前基线。若改写前未确认、文件当时已脏或上次压缩中断，
   保留不确定内容；不显示正文 diff 或回读旧版本来补证，也不为压缩插入额外提交。
2. Done 按交付成果归并，保留结果、产物路径和可核对的验收；删除逐次操作流水，通常收拢至十项以内。
3. Decisions 保留仍有效的选择、理由和会影响后续工作的排除项；被替代的判断和重复讨论收拢为摘要。
   **当前正文允许摘要化，判断历史必须可追溯**，不要求无限追加原文。
4. Intent、未完成 Next、有效 Constraints、Do not、未解决 Open questions 保持完整；Next 第一条
   仍须自包含。不能把接棒必需信息只留成历史链接。
5. 在被压缩的小节附完整提交 SHA 和**该提交内的原文件路径**，例如：
   `历史详情（仅用户要求读取时使用）：<完整提交 SHA>:.agents/tasks/current.md`。
   归档后路径可能已变，来源仍指压缩前的路径；不要用会移动的 HEAD 作为永久来源。
6. 用本次输入核对摘要是否丢失结果、约束、未解决事项或决策含义；不为验收自动回读已压缩的历史原文。

用户要求整理现有归档时，先读归档当前正文；短小清晰的文件不改。需要压缩的文件保留文件名及
frontmatter 原样，保留当时事实，不把后来认识写成当时结论。归档改写前也只用对象存在性与
`git diff --quiet HEAD -- <归档路径>` 的状态码确认当前输入已提交；不显示正文 diff。来源引用同样
受「读取边界」约束。

## 完成与归档

先走完「交棒」的状态更新及长度检查，确认 Intent 和验收达成、Next 为 `- (none)`、无未解决阻塞。
归档摘要保留目标、成果、验收、关键决策、有效限制及明确的非阻塞遗留；保留最后一次 ack。

替换下列占位符后执行一次。**先创建目录**：Git 不保存空目录，clone 后首次归档时它可能不存在。
**先暂存修改再移动**，以确保归档提交带上最新任务状态。已有同名归档时停止，不能覆盖。

```sh
mkdir -p .agents/tasks/archive &&
test ! -e .agents/tasks/archive/<task>.md &&
git add <本轮产物路径> .agents/tasks/current.md &&
git mv .agents/tasks/current.md .agents/tasks/archive/<task>.md &&
git commit -m "<英文单行总结>" -m "Task-Id: <task>
Hop: <hop>
Agent: <agent>" &&
git show HEAD:.agents/tasks/archive/<task>.md &&
sh "<skill-dir>/scripts/ledger.sh" <task>
```

命令用 `&&` 串接，存在性检查、移动或提交任一步失败都不再继续后续步骤。
检查归档提交里的实际内容、trailer 和账本，不只看 diff 统计。上面的 `git show` 仅核对本轮新提交的
归档摘要，不是读取压缩前原文。归档后才能合并回主干，避免多任务分支的 `current.md` 路径冲突。

## 建棒

没有活动任务且需要登记当前工作时，先看当前用户要求。**用户已经明确给出的 Intent、进展和禁区
直接采纳，不重复提固定的三个问题。** 只补问会影响下一步的缺项；没有证据的目标不能从项目结构猜。

需要取证时检查工作区、最近提交摘要、stash 元数据和项目规则；不自动读取历史正文或全部归档。
例如 `git status --porcelain`、`git diff --stat`、`git log --oneline -20`、`git stash list`。
多件无关工作且当前请求未选定时，让用户选一件，不合并成一个 Intent。Constraints 取自项目规则。

先创建任务分支（已有本任务分支则沿用），再读取全局 `assets/TEMPLATE.md` 并写入
`.agents/tasks/current.md`；主干上不放 `current.md`。只有用户明确要求建棒或明确要求登记延续性工作时
才可创建该文件。建棒格式：

- task 为 `t-YYYY-MM-DD-<小写英文短名>`，全仓库唯一、创建后不变。
- 尚有待确认的意图或禁区时使用 `status: draft`、`hop: 0`、空 owner/ack，在 Open questions 写清
  哪些内容是推断或缺失；草稿 Next 可以是待确认问题。
- 当前会话已明确确认或用户补齐信息后转为 `in_progress`、`hop: 1`，清除已解决的问题，把 Next
  改成可执行且自包含的步骤，再按接棒流程填 owner/ack。
- updated 用完整 ISO8601 时区时间；七个小节都保留，空小节写 `- (none)`。Done 只放已完成成果，
  分支名、干净工作区等取证结果不是 Done。

## 抢救：上一棒未留交接

任务棒缺失或陈旧不自动授权读取会话历史，也不放宽压缩历史的读取边界。

1. 先说明拟读取的具体会话文件和工具；当前会话没有相应明确同意时，取得同意后才能读。不同意则
   依当前用户提供的信息建棒，不碰 session 文件。
2. 用现成工具（如 `catchup`、`cli-continues`）提取本任务的目标、进展和判断；不带入其他项目、
   凭据或私人对话，不整段复制日志。
3. 结果经用户过目确认后再写入任务棒，Open questions 注明可能遗漏。任务棒会进入 Git，信息筛选
   必须在写入前完成；明确的当前会话授权不重复索取。
4. 回到正常接棒流程。本仓库不实现各家 session 解析。
